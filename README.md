## Описание
### [Сервис для работы с ПВЗ](https://github.com/avito-tech/tech-internship/blob/main/Tech%20Internships/Backend/Backend-trainee-assignment-spring-2025/Backend-trainee-assignment-spring-2025.md)
На ПВЗ несколько раз в день привозят новые товары, которые были заказаны через Авито. Прежде чем их отдавать заказчику, необходимо сначала проверить и внести информацию в базу. Из-за того, что ПВЗ много, а товаров ещё больше, нужно реализовать механизм, позволяющий в разрезе каждого ПВЗ увидеть, сколько раз в день к ним приезжали товары на приёмку и какие товары были получены.

## API
### Описание API эндпоинтов
#### <ins>**Авторизация**</ins>
***POST*** /register - Регистрация нового пользователя  
***POST*** /login - Авторизация пользователя  
***POST*** /dummyLogin - Получение тестового токена  
#### <ins>**ПВЗ**</ins>
***POST*** /pvz - Создание ПВЗ (только для модераторов)  
***GET*** /pvz - Получение списка ПВЗ с фильтрацией и пагинацией  
***POST*** /pvz/{pvz_id}/close_last_reception - Закрытие последней открытой приёмки  
***POST*** /pvz/{pvz_id}/delete_last_product - Удаление последнего добавленного товара  
#### <ins>**Приёмки**</ins>
***POST*** /receptions - Создание новой приёмки товаров  
#### <ins>**Товары**</ins>
***POST*** /products - Добавление товара в текущую приёмку  
#### <ins>**Проверка**</ins>
***GET*** /health - Проверка функционирования сервиса

## Взаимодействие с БД
Так как по условию задания было запрещено использовать ORM для взаимодействия с базой данных, то в проекте была реализована работа с SQL запросами (находятся в директории app/db/queries), где для каждой сущности (auth, pvz, reception, product) созданы отдельные модули с функциями, возвращающими SQL запросы и параметры. Используются параметризованные запросы с заполнителями (%s) и отдельным списком параметров. Библиотека psycopg2 автоматически экранирует параметры для предотвращения SQL-инъекций. Pydantic модели проверяют входные данные до выполнения SQL запросов. Помимо этого, используются контекстные менеджеры для гарантированного завершения транзакций, а также реализован автоматический rollback при ошибках.

## Инструкция по запуску
1. Клонируем репозиторий и переходим в целевую папку:

```
git clone https://github.com/valkievan/Avito-pvz.git
cd Avito-pvz
```

2. Собираем и запускаем контейнер:

```
docker-compose up --build
```
Миграции применяются автоматически во время запуска контейнера

*После запуска API будет доступен по адресу: http://localhost:8080*
## Тесты
Для тестирования используется фреймворк **Pytest**. Суммарное тестовое покрытие проекта составляет **86%**.
Unit-тесты находятся в папке tests/unit. В папке tests/integration находится интеграционный тест, который:
1) Создает новый ПВЗ
2) Добавляет новую приёмку заказов
3) Добавляет 50 товаров в рамках текущей приёмки заказов
4) Закрывает приёмку заказов
